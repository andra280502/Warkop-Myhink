## 🌐 Enterprise Overview

**Warkop Myhink V3** dirancang untuk operasi otonom berkinerja tinggi. Platform ini meninggalkan arsitektur POS konvensional dengan mengintegrasikan **Swarm Intelligence**, manajemen data desentralisasi (*Offline-First*), dan pemrosesan latensi rendah melalui *Progressive Web App* (PWA) berstandar *enterprise*.

Fokus utama infrastruktur ini adalah resiliensi absolut: operasional cabang tidak akan pernah terhenti akibat kegagalan konektivitas maupun transisi pembaruan *server*.

## 🏗️ Core Architecture

<table align="center">
  <tr>
    <td width="50%" valign="top">
      <b>🧠 Swarm Intelligence Architecture</b><br>
      Sistem membagi beban komputasi analitik ke berbagai model AI global secara dinamis:
      <ul>
        <li><b>Gemini & Claude:</b> Analisis metrik finansial, proyeksi margin, dan <i>Behavioral Engine</i> untuk pelanggan.</li>
        <li><b>DeepSeek:</b> <i>Deep Reasoning</i> untuk audit anomali data penjualan.</li>
        <li><b>Local Node (Ollama):</b> Opsi komputasi <i>on-premise</i> untuk data sensitif tanpa ketergantungan API pihak ketiga.</li>
      </ul>
    </td>
    <td width="50%" valign="top">
      <b>⚡ Zero-Downtime Deployment (OTA)</b><br>
      Pembaruan sistem tanpa menginterupsi transaksi.
      <ul>
        <li><b>Broadcast Reload:</b> Otoritas sistem dapat memancarkan sinyal pembaruan (UI/Algoritma) ke seluruh terminal cabang (POS/KDS) secara serentak.</li>
        <li><b>Frictionless Sync:</b> Pembaruan diunduh di latar belakang dan diterapkan seketika tanpa perlu <i>server restart</i>.</li>
      </ul>
    </td>
  </tr>
  <tr>
    <td width="50%" valign="top">
      <b>🚀 Low-Latency KDS & POS</b><br>
      <ul>
        <li>Kalkulasi kasir adaptif dengan dukungan <i>Web Bluetooth ESC/POS</i>. <i>Payload</i> transaksi dikirim ke layar <i>Kitchen Display System</i> via <i>WebSocket</i> di bawah 50ms.</li>
      </ul>
    </td>
    <td width="50%" valign="top">
      <b>📶 Decentralized Offline-First</b><br>
      <ul>
        <li>Ketika terdeteksi anomali jaringan, transaksi diisolasi ke dalam <i>Mutation Queue</i> lokal (IndexedDB). Sinkronisasi <i>cloud</i> berjalan otomatis saat konektivitas kembali stabil.</li>
      </ul>
    </td>
  </tr>
</table>

## 🔐 Identity & Access Management (IAM)

Pengendalian akses berjenjang berbasis protokol *Role-Based Access Control* (RBAC):

- **[ L1 ] ROOT (Owner):** Kendali penuh ekosistem. Pemilihan *engine* AI, peluncuran *OTA updates*, audit metrik finansial global, dan kontrol arsitektur antarmuka (*Workspace Customizer*).
- **[ L2 ] COMMAND (Manager):** Manajemen inventaris logistik, konfigurasi parameter harga, dan evaluasi matriks performa operasional.
- **[ L3 ] OPERATIONAL (Cashier):** Akses terminal POS, otorisasi transaksi QRIS, dan manajemen *state* meja.
- **[ L4 ] PRODUCTION (Barista/Chef):** Akses mode-baca dan kontrol status antrean pesanan pada layar *Kitchen Display System*.
- **[ L5 ] EXTERNAL (Customer):** Visibilitas terbatas pada katalog digital, pemesanan nirkontak via kode QR, dan portal loyalitas.
